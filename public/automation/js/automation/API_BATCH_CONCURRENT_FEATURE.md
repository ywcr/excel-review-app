# API 批量并发执行功能

## 功能概述

新增 `automaticApiFast()` 函数，支持批量并发执行问卷创建任务，与联系人创建的 `startAddContactFast()` 功能类似。

## 使用方法

### 基本用法

```javascript
// 使用默认批次大小（10个/批）
automaticApiFast();

// 自定义批次大小
automaticApiFast(5); // 每批5个并发
automaticApiFast(20); // 每批20个并发

// 指定日期
automaticApiFast(10, "09.06"); // 每批10个，只处理9月6日的数据
```

### 参数说明

| 参数         | 类型   | 默认值 | 说明                                    |
| ------------ | ------ | ------ | --------------------------------------- |
| `batchSize`  | Number | `10`   | 每批并发执行的任务数量                  |
| `targetDate` | String | `null` | 可选，筛选特定日期的数据（格式：MM.DD） |

## 执行模式对比

### 串行模式（`automaticApi`）

```javascript
automaticApi();
```

**特点**：

- ✅ 安全稳定
- ✅ 对服务器压力小
- ❌ 速度较慢
- 📊 每个任务间隔 5 秒（可调整）

**时间线**：

```
任务1 → 等待5秒 → 任务2 → 等待5秒 → 任务3 → ...
```

### 并发模式（`automaticApiFast`）

```javascript
automaticApiFast(10); // 每批10个并发
```

**特点**：

- ✅ 速度快
- ✅ 批次间有短暂延迟（200ms）
- ⚠️ 对服务器压力较大
- ⚠️ 可能触发限流

**时间线**（批次大小=10）：

```
批次1: 任务1-10 同时执行 → 等待0.2秒 → 批次2: 任务11-20 同时执行 → ...
```

## 性能对比

假设有 100 个任务，每个任务耗时 2 秒：

| 模式 | 批次大小 | 总耗时              | 说明                      |
| ---- | -------- | ------------------- | ------------------------- |
| 串行 | 1        | ~700 秒 (11.7 分钟) | 100 × (2 秒 + 5 秒)       |
| 并发 | 10       | ~22 秒              | 10 批 × 2 秒 + 9 × 0.2 秒 |
| 并发 | 20       | ~12 秒              | 5 批 × 2 秒 + 4 × 0.2 秒  |

**速度提升**：并发模式比串行模式快 **30-60 倍**！

## 使用建议

### 推荐场景

1. **大量任务需要快速完成**：

   ```javascript
   automaticApiFast(10); // 默认批次
   ```

2. **服务器性能较好**：

   ```javascript
   automaticApiFast(20); // 增加批次大小
   ```

3. **测试阶段**：
   ```javascript
   automaticApiFast(5); // 较小批次，便于观察
   ```

### 保守场景

1. **服务器性能一般**：

   ```javascript
   automaticApiFast(5); // 减小批次大小
   ```

2. **担心触发限流**：

   ```javascript
   automaticApi(); // 使用串行模式
   setApiInterval(10000); // 增加间隔到10秒
   ```

3. **生产环境首次使用**：
   ```javascript
   automaticApiFast(3); // 极小批次，观察效果
   ```

## 安全机制

### 1. 批次间延迟

每个批次完成后，等待 **200ms** 再开始下一批次，避免服务器压力过大。

```javascript
// 批次间短暂延迟（200ms）
if (i + batchSize < dataToProcess.length) {
  console.log("⏱️  批次间延迟 0.2秒...");
  await new Promise((resolve) => setTimeout(resolve, 200));
}
```

### 2. 达标检测

如果检测到任务数量已达标，立即停止处理后续批次。

```javascript
if (result && result.isQuotaReached) {
    quotaReached = true;
    console.log('🎯 检测到任务数量已达标，停止处理');
    break;
}
```

### 3. 错误处理

每个任务的错误不会影响其他任务的执行。

```javascript
try {
  const result = await createTaskApi(item.name, item.sex, item.time);
  // ...
} catch (error) {
  console.error(`❌ 失败: ${item.name}`, error);
  return { success: false, name: item.name, error: true };
}
```

## 注意事项

### ⚠️ 服务器压力

并发模式会同时发送多个请求，可能导致：

- 服务器 CPU 使用率上升
- 数据库连接数增加
- 触发 API 限流

**建议**：

- 首次使用时从小批次开始（如 5）
- 观察服务器响应时间
- 如果出现大量失败，减小批次大小

### ⚠️ 错误率

并发模式下，如果服务器压力过大，可能导致：

- 请求超时
- 连接被拒绝
- 响应错误

**解决方案**：

- 减小批次大小
- 切换到串行模式
- 增加批次间延迟（需修改代码）

### ⚠️ 日志混乱

并发执行时，日志可能交错显示，不如串行模式清晰。

**解决方案**：

- 使用批次编号和全局索引定位任务
- 查看最终统计结果

```javascript
// 如果出现错误，减小批次

```
