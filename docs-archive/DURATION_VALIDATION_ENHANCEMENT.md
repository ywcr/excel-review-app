# 拜访时长验证增强功能说明

## 问题背景

在实际使用中，用户填写"拜访时长"字段时会使用多种格式，例如：
- `60` （纯数字）
- `60分钟` （带中文单位）
- `1小时` （小时格式）
- `1.5小时` （小数小时）
- 等等

原有的验证逻辑只是简单地将值转换为数字，无法正确处理带单位的情况，导致验证失败。

## 解决方案

增强了 `parseDuration` 函数，使其能够智能解析多种时长格式，并统一转换为分钟数进行验证。

### 支持的格式

#### 1. 纯数字格式
- `60` → 60分钟
- `100` → 100分钟
- `60.5` → 60.5分钟

#### 2. 带中文单位的格式
- `60分钟` → 60分钟
- `60 分钟` → 60分钟（支持空格）
- `90分` → 90分钟
- `1小时` → 60分钟
- `1.5小时` → 90分钟
- `2时` → 120分钟

#### 3. 带英文单位的格式
- `60min` → 60分钟
- `90mins` → 90分钟
- `60 minutes` → 60分钟
- `1hour` → 60分钟
- `2hours` → 120分钟
- `1.5h` → 90分钟

#### 4. 复合格式
- `1小时30分钟` → 90分钟
- `2小时15分钟` → 135分钟
- `1时30分` → 90分钟
- `1h30m` → 90分钟
- `1 小时 30 分钟` → 90分钟（支持空格）

### 验证规则

根据不同的任务类型，拜访时长有不同的最低要求：

| 任务类型 | 最低时长要求 |
|---------|-------------|
| 药店拜访 | ≥ 60分钟 |
| 等级医院拜访 | ≥ 100分钟 |
| 科室拜访 | ≥ 100分钟 |
| 基层医疗机构拜访 | ≥ 100分钟 |
| 民营医院拜访 | ≥ 100分钟 |

## 代码修改

### 修改文件
- `src/lib/frontendValidator.ts`

### 主要变更

1. **新增 `parseDuration` 方法**
   - 智能解析多种时长格式
   - 返回统一的分钟数，或在格式无效时返回 `null`

2. **修改 `isValidDuration` 方法**
   - 调用 `parseDuration` 方法进行解析
   - 与配置的最低时长要求进行比较

## 注意事项

1. **大小写不敏感**：英文单位支持大小写（如 `MIN`、`min`、`Min` 都可以）

2. **空格容错**：支持数字和单位之间有空格（如 `60 分钟`）

3. **负数拒绝**：负数会被视为无效格式返回 `null`

4. **空值处理**：空字符串、`null`、`undefined` 都会返回 `null`

5. **单位转换**：所有带"小时"或"hour"的输入会自动转换为分钟数

## 向后兼容性

✅ 完全向后兼容

原有的纯数字输入方式不受影响，所有现有数据依然有效。新增功能只是扩展了支持的格式范围，不会破坏现有功能。

## 用户体验改进

✨ 用户现在可以使用更自然的方式填写拜访时长，例如：
- 直接写 `60分钟` 而不必担心系统无法识别
- 可以使用 `1.5小时` 这样更直观的方式
- 支持习惯使用英文单位的用户

这将大大降低用户因格式问题导致验证失败的情况，提升用户体验。
