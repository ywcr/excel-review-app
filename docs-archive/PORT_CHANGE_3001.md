## 🔧 其他端口配置

### 使用特定端口

如果你想使用其他端口，有几种方法：

#### 方法 1: 修改配置文件（推荐）

编辑 `scripts/dev-start.js`:
```javascript
preferredPorts: [你的端口, 3001, 3002, ...],
```

#### 方法 2: 使用环境变量

```bash
# Windows PowerShell
$env:PORT=8080; npm run dev

# Windows CMD
set PORT=8080 && npm run dev

# Linux/Mac
PORT=8080 npm run dev
```

#### 方法 3: 直接启动 Next.js

```bash
npx next dev -p 你的端口号

# 例如
npx next dev -p 8080
```

## 🎯 常见场景

### 场景 1: 多项目开发

现在你可以：
- 项目 A 使用端口 3000
- **本项目使用端口 3001** ⭐
- 其他项目使用 3002, 3003...

不会再有端口冲突！

### 场景 2: 避开常用端口

如果你的 3000 端口经常被其他服务占用（如其他开发服务器），使用 3001 可以避免冲突。

### 场景 3: 固定端口

如果你的前端项目需要固定访问 3001 端口的 API，现在后端也在 3001，更方便了。

## 📝 注意事项

### 环境变量配置

如果你有 `.env` 或 `.env.local` 文件，可能需要更新端口配置：

```env
# .env.local
NEXT_PUBLIC_API_URL=http://localhost:3001
```

### 代理配置

如果你使用了 Nginx 或其他反向代理，记得更新配置：

```nginx
# nginx.conf
location / {
    proxy_pass http://localhost:3001;
}
```

### 防火墙设置

确保端口 3001 没有被防火墙阻止：

```bash
# Windows 防火墙
netsh advfirewall firewall add rule name="Next.js Dev Server" dir=in action=allow protocol=TCP localport=3001

# 查看端口是否开放
netstat -ano | findstr :3001
```

## 🐛 故障排除

### 问题 1: 端口 3001 也被占用

**解决方案**:
脚本会自动尝试下一个端口 (3002)，无需担心。

### 问题 2: 想强制使用 3001

```bash
# 先停止占用 3001 的进程
netstat -ano | findstr :3001
taskkill /F /PID <PID>

# 然后启动
npm run dev
```

### 问题 3: 浏览器记住了旧端口

清除浏览器缓存或使用隐私模式打开 `http://localhost:3001`
