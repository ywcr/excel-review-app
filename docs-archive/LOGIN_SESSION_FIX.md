# 登录过期问题修复说明

## 🐛 问题描述

用户反馈：时不时就需要重新登录，有时重新打开就显示登录过期了。

## 🔍 问题原因

经过代码分析，发现了以下几个导致频繁登录过期的问题：

### 1. **30分钟无活动自动登出** ❌
```typescript
// 旧配置
ACTIVITY_TIMEOUT: 30 * 60 * 1000, // 30分钟无活动就登出
```
这是最主要的问题！如果用户30分钟不操作（比如去开会、吃饭），回来就会被强制登出。

### 2. **开发环境token仅24小时** ❌
```typescript
// 旧配置
JWT_EXPIRES_IN: process.env.NODE_ENV === "production" ? "365d" : "24h"
COOKIE_MAX_AGE: process.env.NODE_ENV === "production" 
  ? 365 * 24 * 60 * 60 * 1000  // 生产环境：1年
  : 24 * 60 * 60 * 1000         // 开发环境：24小时 ❌
```
在开发环境下，每天都需要重新登录。

### 3. **服务端24小时会话清理** ❌
```typescript
// 旧配置
const maxAge = 24 * 60 * 60 * 1000; // 24小时后清理会话
```
即使token还有效，服务端会在24小时后清理会话。

### 4. **心跳检测过于频繁** ⚠️
```typescript
// 旧配置
HEARTBEAT_INTERVAL: 5 * 60 * 1000, // 每5分钟检测一次
```
频繁的心跳检测可能导致不必要的会话验证失败。

## ✅ 修复方案

### 1. 延长无活动超时时间
```typescript
// 新配置 - useAuth.ts
ACTIVITY_TIMEOUT: 24 * 60 * 60 * 1000, // 24小时无活动超时（从30分钟延长）
```
**效果**：用户可以长时间离开（如过夜），回来仍然保持登录状态。

### 2. 统一使用长期token
```typescript
// 新配置 - auth-config.ts
JWT_EXPIRES_IN: "365d", // 所有环境统一使用1年过期时间
COOKIE_MAX_AGE: 365 * 24 * 60 * 60 * 1000, // 所有环境统一使用1年
```
**效果**：开发环境和生产环境都不需要频繁登录。

### 3. 延长服务端会话清理时间
```typescript
// 新配置 - auth.ts
const maxAge = 365 * 24 * 60 * 60 * 1000; // 365天后才清理会话
```
**效果**：服务端不会过早清理有效会话。

### 4. 优化心跳检测间隔
```typescript
// 新配置 - useAuth.ts
HEARTBEAT_INTERVAL: 15 * 60 * 1000, // 15分钟心跳检测（从5分钟延长）
EXPIRY_WARNING_TIME: 30 * 60 * 1000, // 剩余30分钟时提醒
```
**效果**：减少不必要的网络请求和验证失败风险。

| **JWT有效期（生产）** | 365天 | 365天 | ✓ 保持 |
| **Cookie有效期（开发）** | 24小时 | 365天 | ⬆️ 365x |

## 🎯 预期效果

修复后，用户体验将大幅提升：

✅ **长期保持登录** - 正常情况下一年内无需重新登录  
✅ **支持长时间离开** - 24小时内离开电脑也不会过期  
✅ **减少网络请求** - 心跳检测从5分钟延长到15分钟  
✅ **统一开发/生产体验** - 两个环境都使用相同的长期会话

## ⚠️ 安全说明

虽然延长了会话时间，但系统仍然保留了以下安全机制：

1. ✓ **单设备登录** - 新设备登录会踢掉旧设备
2. ✓ **密码保护** - 仍需正确的用户名和密码
3. ✓ **HTTPS加密** - 生产环境强制使用HTTPS
4. ✓ **HttpOnly Cookie** - Cookie不能被JavaScript访问
5. ✓ **会话验证** - 每15分钟进行一次会话有效性检查

## 📝 后续优化建议

如果仍然遇到登录问题，可以考虑：

1. **完全禁用无活动超时**
   ```typescript
   // 在 useAuth.ts 中注释掉活动超时检测
   ```

2. **增加token自动刷新**
   - 当token临近过期时自动刷新

   - 让用户选择是否保持长期登录
   - 不选择则使用较短的会话时间
